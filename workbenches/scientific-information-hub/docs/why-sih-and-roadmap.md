# Why SIH: product introduction and iteration roadmap

## SIH 是什么

SIH（Scientific Information Hub）是一个面向医疗、生命科学以及 AI × 医疗交叉领域的
信息基础设施。它的目标不是抓取尽可能多的内容，而是把分散的专业信息转换成一组
**及时、相关、可追溯、可被人和 Agent 共同使用的记录**。

医疗与生命科学领域每天都会产生大量论文、工具更新、研究方法、作者动态和行业信号。
真正困难的不是搜索，而是持续回答这些问题：

- 哪些内容是今天真正新增或发生变化的？
- 哪些来源已经成功更新，哪些来源今天失效了？
- 同一项工作是否被多个来源重复报道？
- 为什么这条信息值得优先阅读？
- 当 Agent 使用这条信息时，能否回到原始来源核验？

SIH 把这些判断放在展示之前完成。它先保存来源记录和健康状态，再进行日期规范化、
稳定身份、增量识别、去重、时效判断和可解释筛选，最后从同一个事实池生成日报、网站、
Agent 输入和受控分发包。

## 为什么推荐使用 SIH

### 1. 减少重复的信息搜集工作

使用者不必每天分别检查期刊、预印本平台、作者主页、工具更新、邮件和收藏系统。
SIH 把不同来源转换成统一记录，并保留来源之间的差异。

### 2. 不用“页面更新了”冒充“信息更新了”

SIH 区分 `new`、`updated` 和 `seen`，同时记录来源当天是否真的访问成功。当天来源不完整时，
系统会显示 `degraded` 或 `failed`，而不是复用旧数据制造“今天一切正常”的假象。

### 3. 筛选规则可以解释和调整

确定性筛选使用公开的 profile、主题权重、来源权重、时效窗口和阅读层级。
可选 LLM 只提供额外的结构化判断，不修改来源事实，也不覆盖确定性阅读层级。

### 4. 人与 Agent 使用同一事实池

人看到的信息流、Markdown 日报与 Agent 读取的 JSONL 来自同一个 `daily_items.jsonl`。
这减少了“网页展示一套、Agent 使用另一套”的漂移，也便于在分析结果中保留原文链接、
发布日期、来源状态和稳定标识。

### 5. 更适合垂直专业场景

通用热点网站解决的是“现在大家在谈什么”；SIH 更关注“哪些变化与一个具体专业方向有关”。
维护者可以围绕医疗 AI、临床研究方法、单细胞与空间组学、类器官、药物研发或其他明确主题，
配置来源和筛选策略，而不需要把真实个人画像公开。

## 对 Agent 友好意味着什么

Agent 友好不是简单地允许爬网页，而是让信息具备稳定、可检查的机器语义：

- 稳定的 `item_id` 和明确的 `new / updated / seen` 事件；
- 标准化的标题、摘要、日期、作者、标签和原始 URL；
- 可区分的来源类型、来源健康和日级完整性；
- 人类阅读层级与可选 LLM 判断分开保存；
- 重要判断能够回到原始论文、官方页面或公开记录；
- 数据不完整时，Agent 能看到失败状态，而不是把缺失误解为“没有新内容”。

当前版本已经生成 JSONL 和 JSON 文件。未来公共服务会在保持这一合同稳定的基础上，增加
适合外部 Agent 使用的只读 Feed/API；是否提供 MCP，将由真实使用场景决定，而不是为了接口数量预先包装。

## 适合哪些使用方式

- 研究人员让 Agent 追踪特定主题、期刊或作者，并生成每日简报；
- 医疗科技与医药研发团队持续观察工具、方法与竞争环境变化；
- 内容创作者从有出处的候选信息中选择题目，再进行人工核验和写作；
- 团队把 SIH 作为内部 Agent 的外部信息入口，减少每个 Agent 重复抓取同一批网站；
- 使用者将新信息与自己的项目、文献库或研究问题关联。

SIH 不是临床决策支持系统，不评价个体诊疗方案，也不把主题匹配度包装成证据等级。
涉及科研结论、临床实践或其他重要决策时，必须核验原始研究、权威指南与适用范围。

## 当前版本：已经具备的能力

`0.1.0-reference` 是可运行、可测试、默认离线的参考实现。

### 来源层

- PubMed、PubMed 期刊集合、arXiv、RSS/Atom、Hacker News；
- OpenAlex 作者追踪；
- 本地 `.eml` 与只读 IMAP；
- Feishu/Lark JSON 导出、Stork JSONL/CSV；
- 用户控制的浏览器登录后规范化 snapshot；
- JSONL/CSV Legacy 字段映射兼容层。

公开网络来源必须同时在配置中启用并传入 `--live`。账号、watchlist、cookie、浏览器 profile、
邮件内容和真实运行数据均不在公开仓库中。

### 处理与筛选层

- PMID、DOI、arXiv ID、canonical URL 等稳定身份；
- `new / updated / seen` 增量事件；
- 日期规范化、时效门、跨源去重和来源 lineage；
- 可配置 profile、主题权重、来源权重和新颖度提示；
- `must_read / skim / collapsed / archive` 四层阅读队列；
- 双重开关的可选 LLM triage；
- `complete / complete_with_warning / degraded / failed` 健康状态。

### 交付层

- `daily_items.jsonl`：唯一组装事实池；
- `source_health.json`：来源和日级健康；
- `daily_briefing.md`：人类阅读日报；
- `site/index.html`：可搜索、可按阅读层级筛选的静态信息流；
- `public_content_candidates.jsonl`：需要人工复核的公开内容候选；
- 三重开关的 HTTPS Webhook：配置启用、`--publish`、环境变量 endpoint。

### 当前尚未提供

- 由维护者持续运行的正式公共网站；
- 稳定的公网 JSON Feed、RSS、REST API 或 MCP 服务；
- 面向终端用户的账号、收藏、订阅和个性化界面；
- 经长期真实运行验证的医疗垂直主题目录；
- 临床证据评级、指南推荐或诊疗建议。

## 持续迭代路线

SIH 的迭代顺序是“先让事实链可靠，再扩大来源和界面”，而不是先堆更多抓取器。

### 阶段一：把真实运行稳定下来

1. 选择一个边界清晰的医疗或生命科学主题作为首个公开频道；
2. 按计划任务每日运行来源、组装、健康检查和静态页面生成；
3. 为 DNS、代理、超时、上游限流和 schema 漂移建立可区分的错误类型；
4. 失败时保留 `degraded` 状态，只重跑失败来源，不把昨日数据伪装成当天结果；
5. 一个来源至少经过连续多次真实运行和 manifest 对账后，才升级为稳定来源。

阶段验收关注：来源成功率、最新内容日期、错误恢复时间、重复率、过期率和日级完整性。

### 阶段二：建立医疗垂直的策展质量

1. 建立主题包：核心检索式、期刊集合、作者集合、官方工具与机构来源；
2. 保存人工判断：值得读、噪声、重复、主题错配和需要补充的来源；
3. 用真实反馈校准 profile 阈值和 LLM triage，而不是只优化演示样例；
4. 对每个公开频道写清覆盖范围、时间窗口和明确不覆盖的内容；
5. 定期审查来源许可、可访问性和元数据质量。

阶段验收关注：高优先级条目的人工接受率、错配率、漏报样本、来源集中度和原文可核验率。

### 阶段三：部署公开信息源网站

1. 将静态页面部署成持续更新的网站，提供日期、主题、来源和阅读层级视图；
2. 在页面上明确显示更新时间、数据覆盖窗口和来源健康；
3. 每条记录保留原始链接，不把自动摘要当成原文；
4. 公开页面只读取经过字段白名单处理的数据，不发布邮箱、账号数据、个人画像或运行日志；
5. 内容候选进入人工审核后才能成为正式公开内容。

展示层可以像持续更新的热点信息站一样易读，但网站不是新的事实数据库；它始终是
`daily_items.jsonl` 及其后续稳定服务合同的投影。

### 阶段四：开放 Agent 读取能力

建议按需求依次提供：

1. 版本化 JSON Feed 和 RSS；
2. 只读 REST 端点，例如 items、sources、health 和 latest briefing；
3. 明确的时间、主题、来源和增量查询参数；
4. 缓存、速率限制、schema version 和弃用策略；
5. 当多个 Agent 的真实工作流需要工具调用时，再提供薄的只读 MCP。

Agent 接口的验收不只看 HTTP `200`，还要检查 schema 稳定性、来源覆盖、时间边界、
失败状态、引用完整性以及是否能从结果返回原始来源。

### 阶段五：形成反馈与治理闭环

1. 记录哪些条目被阅读、保存、忽略或判定为不相关，但不公开真实用户画像；
2. 建立固定评测集，防止筛选策略调整后出现无声退化；
3. 定期发布来源与 schema 变更记录；
4. 将公开站运营、代码发布、数据更新和外部内容发布视为四个独立动作；
5. 对医疗相关内容持续保留人工核验、来源引用和非诊疗声明。

## 每次迭代的最小闭环

```text
提出一个来源或筛选改动
  -> 用合成 fixture 做离线测试
  -> 用真实来源做受限 smoke test
  -> 连续观察 health / manifest
  -> 人工抽查高优先级与漏报样本
  -> 更新 schema、文档与变更记录
  -> 再进入公共网站或 Agent 接口
```

一个新 Adapter “成功抓到一次”不等于已经成为可靠信息源；一个新页面“能够打开”也不等于
Agent 可以安全使用。SIH 的持续价值来自可观测、可核验、可回退的迭代过程。

## 对外一句话

> SIH 是一个面向医疗与生命科学领域的人与 Agent 的垂直信息源：持续采集、筛选并发布
> 可追溯的信息，让专业人士和他们的 Agent 更方便地获取真正相关的新进展。

更短的传播表达：

> 不是提供更多信息，而是让你和你的 Agent 更早发现真正重要的信息。
