# 试用版验收

## Gate 0：安装与迁移

1. `scripts/bootstrap.py doctor` 显示受管 Python 为 3.12、pdf2zh 与必需 imports 可用、模型和字体资产校验通过。
2. 使用临时 `HOME` 跑双生态安装器，Codex 副本位于 `.agents/skills/`、Claude 副本位于 `.claude/skills/`，两处均包含完整 `SKILL.md`、scripts、references 和 assets，且不包含 `__pycache__`。
3. `scripts/launch.py start --dry-run` 解析到受管 Python 和受管 pdf2zh；真实启动后 `/api/health` 中 server Python 与 engine Python 一致。
4. 在空白临时 `HOME` 中运行 `scripts/prefetch_assets.py`，必须从可用镜像下载并哈希校验 4 项最小资产；不得因为 Hugging Face 单一上游 403 而失败。
5. 安装结束清除可重建的 uv 下载缓存；当前 arm64 实测受管运行时约 990 MiB，模型与字体缓存约 113 MiB。
6. 纯文本 PDF 的安装与运行不得触发 PaddleOCR 下载；只有任务预检命中 OCR 页且用户在页面明确确认约 1–2 GB 后，才可执行 `scripts/bootstrap.py ocr-install --yes`。
7. `scripts/bootstrap.py ocr-doctor` 必须报告独立路径、锁文件匹配、Python 3.12、Paddle/PaddleOCR/PaddleX/PyMuPDF/OpenCV 导入和模型资产清单；不得复用系统 Python 或历史 Conda 环境。

## Gate 1a：工作台

1. 页面只绑定本机地址，刷新后任务仍存在。
2. 上传非 PDF 或超过 500 MB 文件会被拒绝。
3. 上传文本型英文 PDF 后可启动 Codex 翻译，并显示排队、翻译、完成或失败状态。
4. 完成后原文和中文 PDF 可在左右面板打开，同一个页码按钮会同时切换两侧。
5. 中文 PDF 可下载，页面显示其实际保存目录。
6. 表格没有被宽幅遮罩破坏；无法可靠翻译的表格允许保留英文。
7. 任务目录生成 `page-plan.json`，其中逐页记录类型、策略、置信度和 QA 结果。
8. 超密表格数据区与原文保持一致，表题区域允许使用译文。
9. 目录续页按结构识别，不依赖固定页码范围。
10. 缩略语页保持缩写代码，逐条翻译释义；普通正文提到“acronyms”不得误判。
11. 正文与表格混排时只保护表格矩形，表格上下正文不得整页退回英文。
12. QA 检查结构化条目数、中文输出、语言异常回退，并单独报告表格区域定位警告。
13. 每个完成任务生成 `bilingual-side-by-side.pdf`；每个物理页面左侧原文、右侧中文，页数与两份输入一致。
14. 网页“预览”和“下载双语”指向同一份合并 PDF；“下载中文”仍可单独导出中文版。
15. 上传面板不随页面滚动，可折叠和展开；标题在桌面宽度下保持单行。
16. “退出程序”在无运行任务时关闭本地服务；有运行任务时返回明确阻止信息。
17. 适合逐格处理的矢量文本表格走 `translate_table_cells`；保持原行列、合并单元格、金额、数字和等级代码。
18. 单元格依次执行换行和字号缩小；最低字号仍放不下时保留该单元格英文并产生 QA warning，不得覆盖相邻单元格。
19. 单元格表格上方表题、下方表注/来源及续表标记形成表格结构包；AI 只翻译确认关联的候选，无关正文保持原流程。
20. 表格关联文字写回失败时保留英文并产生 QA warning；不得因为邻近位置而误覆盖正文、页码或页眉页脚。
21. 每个新完成任务生成 `qa-alpha.json`，包含逐页问题类型、严重度、证据、渲染指标和问题页列表。
22. QA 同时使用文本层和96dpi渲染层；只检查 CJK 数量、页数或结构化条目不得判定通过。
23. 严重问题将任务状态改为 `NEEDS_REVIEW`；UI 仍允许预览和下载草稿，但不得显示为最终完成。
24. 本地已知缺陷基准的25个问题页必须全部标红；建立好页标注前必须声明误报率未知。
25. 问题页修复试验必须保存修前、修后和映射；结构化回填的 `targets` 必须等于 `placed`，放不下时必须恢复原内容，不得留下空白单元格。
26. 修复策略必须在同一问题页上复跑 Gate 1c-alpha；修后 critical 数不得增加，且页面级确定性通过不能替代人工视觉复核。
27. 修复翻译项必须先去重并查询任务级缓存；AI 请求使用稳定 ID JSON，单轮默认不超过 12 次调用，缺失项最多一次成组重试。
28. `--full` 只重建目标问题页，非目标页必须从现有译文无损复制；安装前必须验证原文、中文和双语 PDF 页数一致。
29. 正式安装必须先备份旧中文 PDF、双语 PDF、逐页计划、QA 和任务状态，再以同目录临时文件原子替换；任何未解析翻译或调用错误都必须阻止安装。
30. 旋转页的表格单元格必须使用旋转坐标校正后回填；表外低置信文字保留英文原位，不得因追求覆盖率产生竖排、越界或错格文字。
31. 安装修复版不得清除全篇风险：QA 仍有 critical 时任务继续显示 `NEEDS_REVIEW`，下载仍按草稿处理。
32. “查看 QA”必须按页展示去重后的问题、证据、严重度和用户复核状态；关闭或重启工作台后，忽略/待复核状态仍存在。
33. “让 AI 分析”只生成结构化诊断，不得修改 PDF；输入只包含用户选择的页、问题证据、页面指标、两张页面截图和用户补充。
34. 只有用户再次确认后才能生成候选修复；候选输出必须隔离在 `repairs/<repair-id>/candidate/`，并重新运行全篇 Gate 1c-alpha。
35. 候选版本 critical 数增加时必须阻止验收；用户拒绝候选时当前下载文件哈希不得变化。
36. 用户接受候选时必须先备份旧中文、双语、QA 和逐页计划，再原子替换；工作台随后展示新的 QA 状态和问题页数量。

## Gate 1b：PaddleOCR 页面级入口

1. 上传后生成 `document-plan.json`；可靠文本页、扫描/稀疏文本页和纯空白页分别标记为 `text`、`ocr`、`blank`，页码从 1 开始。
2. 24 页非敏感合成金标准由 `scripts/ocr_acceptance.py generate` 生成；预期 6 个文本页、6 个清晰扫描页、6 个降质扫描页和 6 个旋转扫描页。
3. 自动页面路由准确率必须为 100%；手工指定页会覆盖自动路由，但页码越界必须拒绝。
4. OCR 固定使用英文 PP-OCRv5 mobile 检测/识别模型、220 dpi 渲染、文档方向校正、去畸变和文本行方向识别；实际配置与模型资产写入可核对清单。
5. 清晰扫描页平均 CER 必须 ≤1%；降质扫描页和旋转扫描页分别必须 ≤5%。评分使用归一化空白与小写后的字符编辑距离，报告逐页 CER。
6. 输出 `ocr-results.json`，逐页记录文本、置信度、像素框、渲染 DPI、旋转元数据、预处理动作与 warning；低平均置信、低行置信和空识别不得被吞掉。
7. 生成 `searchable-original.pdf`：OCR 页以处理后图像为可见层、识别文本为不可见可搜索层；非 OCR 页保持原 PDF 内容；原始 `original.pdf` 哈希不得改变。
8. 原文、可搜索原文、译文和双语 PDF 的页数及顺序必须 100% 一致；缺少任何 OCR 页结果必须失败，禁止静默生成空白页。
9. 只有 OCR warning 而没有确定性 QA critical 时，任务进入 `COMPLETED_WITH_WARNINGS` 并继续提供译文；warning 页码和原因必须在 UI 可见且可下载 JSON。
10. OCR 模型安装失败或用户取消安装时，任务保持可恢复的等待/错误状态；不得破坏文本型翻译运行时或其他任务。
11. 合成金标准通过后，还需一份 June 自选的真实英文扫描 PDF 做本机端到端验收；真实文件、截图、原文和 OCR 全文不得写入 Git、看板或聊天，只记录非敏感计数、CER/抽检结论和产物路径。

## 暂不作为通过条件

- 独立 JPG/PNG/HEIC 与批量图片导入
- 中文或多语言扫描件 OCR
- 文本页内任意手绘矩形的框选 OCR（v1 支持已检测嵌入图片的单独按钮，不支持自由框选）
- 滚动像素级同步
- 后台重启续跑、暂停与恢复
- 术语表、段落编辑和局部重译
