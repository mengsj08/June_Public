| 输入情景 | 合理处理 | 应拦下的结论 |

| 4月25日宣布计划5月底供货；5月16日报已开始交付 | 两条事件；用后者支持已供货，不发明首笔交付日 | 4月25日已开售，或5月31日才上市 |

| 家用A、旅行M、生命支持V共享部分技术，发布时间依次更晚 | 按用途并行分支；只对明确后继画代际边 | A→M→V是三代产品 |
| 新机宣传“AI Comfort 6”；旧手册已有自动湿化，暂缺新版手册 | 成熟功能延续是有据基线；新增条件适配/控制变化待核，可作条件性判断 | 版本6证明六次算法发明；或确定只是换标签 |
| 专利2023申请，从呼吸预测中间信号；2026产品宣称睡眠分期 | 记录技术候选与主张，新输出可能有增量；中间信号到分期及量产采用仍需证据 | 研发2023才开始；专利证明该机已实现准确分期 |
| 官网旧型号今日写有AI；同期说明书只有自动控制；历史报道称“近日首次亮相” | 今日措辞记录在观察日；同期能力按手册；亮相最迟在报道日，保留精度 | 把今日AI文案回填旧型号首发日；报道日等于活动日 |
| 公司历史页与当年年报的月份不同 | 比较地区和事件类型；无法消解则保留冲突，主图取共同支持的年份 | 选看起来更新的网页覆盖年报，隐去冲突 |
| 公司收购已有检测器；App随后导入其结果 | 收购、既有产品与数据接入分别记录 | 收购时发明检测器；App本身完成检测 |

应用到真实研究时再核验来源，不照搬案例的结论。合格交付应让读者找到关系依据、正确时间口径、功能增量及判断边界，而不只是看到完整的表格形式。

## 交互与交付校准

| 情景 | 合理动作 | 应避免的处理 |
|---|---|---|
| 已明确做全球全型号盘点，读者要快速看懂主干 | 正文概括分支，全量台账放附件并保留覆盖缺口 | 为精简页面悄悄改成代表型号研究；重问已定范围 |
| 同一品牌跨消费与医疗多条线，用途尚不明确 | 用简版版图说明范围选项，询问侧重认清产品线、追溯发布还是分析演进 | 默认所有分支都深挖专利，或自行排除一半产品 |
| 用户对图中分组有偏好，但来源未证实某代际箭头 | 调整展示分组，关系标待核并继续核验 | 让用户选哪个发布日期是真的，或按偏好确认后继关系 |
| 关键首发日期不可得，长尾补查会改变投入 | 展示已成立的时间范围、缺口影响及继续查的选项；普通查证自主完成 | 默认为精确日期；每查一份来源都要求批准 |
| 客户只需要竞品族谱，工作目录另有我方规划、个人讨论和历史快照 | 交付选定图表与支撑材料，按约定排除无关附件并核对深层链接 | 整个目录上传；把历史讨论默认塞入附录 |
| 用户从族谱继续要求我方功能设计 | 复用产品/功能/事件/来源记录，确认尚缺的责任范围与输入条件后继续 | 重做一遍族谱；在此前未要求时提前生成我方开发排期 |

这些场景用于内容自查，不作为原生调用或独立真实任务通过凭据。
