# 证据与关系规则

## 按问题选证据

| 研究问题 | 优先资料 | 可支持什么；不能越过什么 |
|---|---|---|
| 何时发布/供货 | 当年发布稿、商业推出表、年报、同期目录 | 依原文区分宣布、计划和实际供货；报道“近日”仅给上界 |
| 地区许可/可用性 | 监管数据库、地区官方公告、当地版本说明 | 许可不等于开售；一地推出不等于全球上线 |
| 当时实际提供什么 | 对应版本手册、发行说明、同期产品规格、可核验操作/输出 | 当前网页只能证明观察时表述，不能证明初代能力；手册描述也不等于效果验证 |
| 前后代/更名关系 | 明确后继或更名声明、同期系列对照、版本/型号标识 | 相同平台可能有不同配置；兼容同一App不等于同代或替代 |
| 功能真实增量 | 新旧版本可比输入输出、操作流程、限制及同条件结果 | 名字改变不证明实现改变；标称指标差异不自动证明实测提升 |
| 技术实现候选 | 说明书、专利全文、技术披露、相关论文 | 专利说明可能路线；不能证明量产采用，申请日也不是研发启动日 |
| 首创与价值 | 有范围的前代/竞品检索；任务完成与效果证据 | 自家新输出不等于行业首次，算法新颖不等于用户收益 |

同一通稿的转载去重到原始发布者；厂商声称、独立测评和研究者推断各自标明。官方历史回顾也可能混淆年代，优先采用明确对应产品、事件与地区的同期资料，保留矛盾而非静默抹掉。

## 冲突处理

先检查是不是不同事件、地区、版本或日期精度，再考虑真正矛盾：

1. 找出双方原文、页面/表格/版本位置，不能只看搜索摘要。
2. 能解释的拆成两条事件，例如预告与供货、首发地区与后续地区。
3. 不能解释的保留两个来源，主表用双方都支持的精度或区间，并标“冲突未解”。
4. 写清采用某口径的理由及可能影响，不按来源数量投票。

当前页面确认有功能但历史首发不明时，写“截至观察日可见，首次上线未核”；找不到前代功能时，写“已检查的资料未见”，不能写成“前代没有”。

## 关系与计数

| 关系 | 画法/记录法 | 常见误判 |
|---|---|---|
| 后继代际 | 有据的前代→后代；标示平台或型号层级 | 发布更晚就连箭头；认为前代已退市 |
| 同代配置/并行用途 | 同组并列或不同分支 | 高配是下一代；旅游产品是中间代 |
| 地区版/别名 | 同实体关联地区版；等价未证实先分开 | 译名相近就合并；全球软件能力套到本地版 |
| 更名 | 明确“更名”边，保留前后名称 | 同类新品误写成更名 |
| 集成/兼容 | 带标签的关联边 | 导入第三方数据被写成自研测量能力 |
| 收购 | 公司归属事件与产品演进分开 | 收购日成为产品首发日 |

型号数、家族数、事件数及功能数分别统计。专利同族、公开/授权文本也分别去重，不能用文献数当作独立发明数。无法证明全集时，报告已识别范围与未覆盖项，不计算无分母的覆盖百分比。

## 最小来源记录

每个 S-ID 保留标题、发布者、资料日期与类型、产品/版本/地区、URL或本地路径、实际访问日期、页码/章节/短摘录以及所支持的具体断言。保存了全文/截图才写“本地存证”；仅取得解析文本时如实标记。
