# popsci 小红书卡片配方库

小红书图文**与长图分流**:不从长图截取,而是从 `brief.md` **重新规划**——一卡一观点、文案压缩、吃满画布。
视觉沿用 popsci 设计系统(暖米黄 + 陶土色),复用长图里的现成组件。

## 第 0 步:选主题 + 接意图(借鉴 huashu-design)
- **先填 brief 顶部「决策」块**:每篇 `brief.md` 开头有一段 yaml 决策字段(平台 / 主题 data-theme / 品牌色 / 温度 / 受众气质)。**开工先读它、没填先填它**——这是意图/主题/品牌的唯一事实源,渲染照此,改风格只改这块。
- **配色不写死**:按 `references/themes.md` 选主题(`data-theme`),或接用户品牌色/意图自定义。**别无脑默认暖色**——医学走 cool-clinical、数据走 swiss-bold、严肃走 ink-editorial。
- **可交人决策**:一次性问平台/受众/风格(用户不答则 AI 按领域定并说明可换),把选定主题记进 brief。
- **给变体、不给唯一解**:必要时出 2–3 个差异化方向(暖/冷/数据)让用户挑,而非自作主张一条道走到黑。

## 硬规则(借鉴 guizang + huashu 反 AI slop)
- **反 AI slop**(必守):不堆「data slop」(没用的数字/stats 装饰)、不堆「icon slop」(每个标题都配 emoji/图标)、不堆「gradient slop」(处处渐变)。每个元素都要 earn its place。
- **诚实占位 > 假数据**:没有真实数据/图就留占位说明,**绝不编造看起来像数据的假数字**。
- **一卡一观点**:每张只讲一件事,不堆叠。
- **文案压缩阶梯**:核心主张 → 读者收益 → 4-8 个观点 → 钩子 → 只留"解释视觉"的碎句。**不要把长图整段塞进卡**。
- **填充 ≥75%**:1080×1440 画布,内容覆盖 ≥75% 高度;严禁用 `flex:1` 上下夹击把内容怼到中段(那是长图/杂志逻辑,社交卡逐张刷会显空)。唯一例外:金句卡(R7)可留白,但必须有顶部章号 + 底部出处两个"锚点"。
- **数字卡密度豁免(重要)**:纯指标卡(只有几个大数字/短条形,如生物医学论文)天然填不满。**目标放宽到 ~68%,且只用真实细节补、绝不注水**——医学/科学内容里「注水」比「留白」更危险。补法:加方法/数据集背景、加一句机制解释、换更"吃画布"的数据配方(下方 R9–R12)。`measure-cards.js --target 68` 单独量这类卡。
- **页面角色多样**:别每张都是"标题+卡片",在下面 8 种角色间轮换。
- **页数**:600-1000 字 → 5-7 卡;1000-1800 字 → 7-9 卡。空页就合并相邻观点。
- **封面用钩子**,不用长标题;**标题用动词+后果**,不用"背景介绍"这类抽象词。

## 密度自适应(偏空就回原文补细节)

把"填充率"做成硬约束,**偏空时优先从同一主题多摘真实细节去填**,而不是把稀疏内容摊开居中。

- **密度带**:内容占卡片可用区(1080×1440 去掉上下 padding)的 **78%–100%** 为合格。
  - `<78%` 偏空;`>100%` 溢出(被裁切)。
  - **封面 / 金句卡豁免**(本就该透气),但必须有锚点:顶部 kicker + 底部出处。
- **检测**:`node scripts/measure-cards.js <case>` —— 纯文字输出每张卡的 `fill%` 与标记,不出图、几乎不耗 token。流程:**Plan → 生成 → measure → 补/调 → 复核**。
- **偏空(<78%)的补充阶梯**(按序尝试):
  1. **回 brief/原文给同一主题多摘细节**:+1–2 个支撑点、一个具体例子、一个次要数字、一句机制/原因、或一张证据图 + 说明。
  2. 仍不够 → 换更"吃画布"的配方(清单 R4 / 数据条 R5 / 阶梯 R6 比纯对比 R3 更密),或把相邻两张**合并**成一张更饱满的。
  3. 主题确实单薄 → 才允许居中留白,且**仅限封面 / 金句**(带锚点)。
- **溢出(>100%)**:反向——精简文案,或拆成两张。
- **红线**:只摘**原文真实细节,不编造、不灌水**;补充的是同一观点的支撑,**不引入第二个观点**(守住一卡一观点)。

## 8 种角色卡(配方)

| # | 角色 | 何时用 | 结构 | 复用组件 | 最小密度 |
|---|---|---|---|---|---|
| R1 | **封面 Hook** | 第 1 张 | kicker + 大钩子标题(核心 6-12 字)+ 1 句副 + 底部 3-4 要点条 + 1 个关键数字 | hero/.chip/.stat | 标题 + 底部要点条 |
| R2 | **问题场景** | 抛痛点/背景 | kicker + 痛点标题 + 1-2 句场景 + 1 个视觉(数字/小流程/对比) | .repbar/.stat/.mirror | 标题 + 场景句 + 1 视觉 |
| R3 | **对比** | 误解vs真相 / 旧vs新 / 双向 | 标题 + 左右(或上下)两栏,各 3-4 短句 | .mirror/.grid2 .card | 标题 + 两栏各 3 句 |
| R4 | **清单/能力** | 列能力、要点、清单 | kicker + 标题 + 4-6 行(编号/圆点 + 条目 + 后果) | .ul-clean | 标题 + ≥4 行 |
| R5 | **数据条形** | 一组对比数字 | kicker + 标题 + 1 组条形(3-5 条)+ 1 句解读 | .bgroup/.bar/.fill | 标题 + ≥3 条 + 解读 |
| R6 | **步骤/流程** | 讲 3-5 步流程 | kicker + 标题 + 3-5 步(编号 + 步骤名 + 一句) | .repbar(竖排) | 标题 + 3-5 步 |
| R7 | **金句/结论** | 制造节奏 / 收一个论点 | 顶部章号 + 超大引言一句 + 出处/语境行 | .cta/大字 | 章号 + 金句 + 出处(三锚点) |
| R8 | **结尾·记住三点** | 最后一张 | 标题 + 3 个要点(pills/ledger)+ CTA/来源 | .cta/.pills | 标题 + 3 要点 + 来源 |

## 数据卡配方扩展(R9–R12,借鉴 guizang Swiss + huashu)
数字密的内容(论文指标、评测、榜单)别只会用「短条形 + 一句话」——那必然偏空。按数据形态选更"吃画布"的:

| # | 角色 | 何时用 | 结构 |
|---|---|---|---|
| R9 | **大数字 Hero** | 单个核心数字撑一卡 | kicker + 一句话题 + 超大 `num-mega`(150–220px)+ 一行注解 + 一句意义 |
| R10 | **KPI 塔** | 3–4 个数字横向对比 | 标题 + 4 列(数字 + 标签 + 高度编码数据的竖条)+ 一句解读 |
| R11 | **H-bar 榜单** | 5–8 项排名/对比 | 标题 + 多行(名称 + 横条 + 数值);宽度编码量级,真实百分比 |
| R12 | **指标矩阵** | 一组能力/多指标一览 | 标题 + 2×N 小格(指标名 + 值)+ 底部一个汇总大数 |

要点:① 数字必须真实、来自原文;② 一卡聚焦一类对比;③ 用「高度/宽度编码」让数据有体量感,而不是干列数字(这才填得满又不注水)。

## 每篇流程
1. 读 `brief.md` → **判断**哪些配方适用(不必 8 种全用,也可微调)。
2. 产出**文字 Page Plan**(下方模板)→ 交用户确认。
3. 按 plan 套配方逐卡写 1080×1440 HTML(`.shot.xhs-card[data-name=xhs-NN]`)。
4. `shoot-cards.js` 渲染 + 拼图复核。

```
标题 / 受众 / 风格:
01 封面(R1)  钩子: …  视觉: …  底部要点: …
02 (R?)      观点: …  文案: …  视觉: …  版式: R?
…
NN 结尾(R8)  三点: …  来源: …
```
