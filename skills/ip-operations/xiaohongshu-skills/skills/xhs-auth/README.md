# xhs-auth

> 小红书登录状态检查、扫码登录、短信验证与安全退出。

`xhs-auth` 只负责认证生命周期，不负责搜索、发布或互动。它通过项目统一 CLI 调用浏览器自动化层，让 Agent 能判断“当前是否已登录”，并在必须由人参与时停下来等待扫码或输入验证码。

## 适用场景

- 检查本机浏览器中的小红书登录状态；
- 获取或刷新登录二维码；
- 等待用户扫码并确认登录完成；
- 经用户当次确认后发送短信验证码；
- 退出登录并清除本项目使用的 Cookie。

## 快速开始

```bash
python scripts/cli.py check-login
```

常用命令：

| 命令 | 作用 | 是否需要人工参与 |
| --- | --- | --- |
| `check-login` | 检查当前登录状态，未登录时可返回二维码信息 | 视结果而定 |
| `get-qrcode` | 获取或刷新二维码 | 是 |
| `wait-login` | 等待扫码完成 | 是 |
| `send-code --phone` | 向当次确认的手机号发送验证码 | 是 |
| `verify-code --code` | 提交用户本轮提供的验证码 | 是 |
| `delete-cookies` | 清除登录态并退出 | 必须确认 |

## 推荐交互

```text
Agent 检查登录状态
  ├─ 已登录 → 返回账号可用，不重复登录
  └─ 未登录 → 展示二维码或询问是否改用短信
                  ↓
              用户完成验证
                  ↓
              Agent 再次检查状态
```

示例提示词：

```text
使用 xhs-auth 检查当前小红书是否已登录。如果未登录，优先给我二维码；不要自动使用历史手机号，也不要输出任何 Cookie 或 Token。
```

## 安全边界

- 每次短信登录都必须重新向用户确认手机号，不能从记忆、历史对话或文件中自动填入；
- 验证码只用于本轮登录，不写入文档、日志或 Git；
- `delete-cookies` 会改变本地登录状态，执行前需明确确认；
- 不打印、复制或迁移 Cookie、Token、浏览器 profile 内容；
- 已登录时不要频繁重新登录或退出，避免触发账号风控；
- 所有认证操作只走根项目 `python scripts/cli.py`，不混用第三方登录工具。
