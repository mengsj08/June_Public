# xhs-content-ops

> 把“找内容、读详情、做分析、写草稿、发布与互动”编排成一个有人类确认闸的运营流程。

`xhs-content-ops` 是组合型 Skill。它不新增一套小红书接口，而是按目标调度 `xhs-explore`、`xhs-publish` 和 `xhs-interact`，让 Agent 在一次任务中保持证据、草稿与外部操作的一致性。

## 适用场景

- **竞品分析**：比较高互动笔记的选题、标题、封面和正文结构；
- **热点追踪**：按关键词、时间和内容类型观察近期变化；
- **内容创作**：先研究同类内容，再形成差异化草稿；
- **运营辅助**：整理可选互动目标，交由用户决定是否执行；
- **飞书沉淀**：将研究结果交给 `topic2feishu-xhs` 入库。

## 默认工作流

```text
明确目标与范围
      ↓
搜索候选笔记（只读）
      ↓
读取有限数量详情（只读、限频）
      ↓
表格化证据与模式分析
      ↓
生成草稿或互动建议
      ↓
用户确认
  ├─ 不执行 → 保留分析和草稿
  └─ 执行   → 调用发布或互动子 Skill
```

默认停在“建议/草稿”，不会因为生成了内容就自动发布。

## 组合命令

该 Skill 会根据任务调用：

- 发现：`search-feeds`、`list-feeds`；
- 证据：`get-feed-detail`、`user-profile`；
- 发布：`fill-publish`、`fill-publish-video`、`click-publish`；
- 互动：`post-comment`、`reply-comment`、`like-feed`、`favorite-feed`。

所有命令统一通过：

```bash
python scripts/cli.py <subcommand>
```

## 推荐输出

分析阶段建议至少返回：

| 内容 | 要求 |
| --- | --- |
| 样本范围 | 关键词、筛选条件、数量与采集时间 |
| 证据表 | 标题、作者、互动数据、正文结构、来源标识 |
| 观察 | 明确区分原始事实与 Agent 推断 |
| 建议 | 选题、标题、内容结构与差异化角度 |
| 草稿 | 可编辑，未确认前不得发布 |
| 未知项 | 读取失败、字段缺失或无法核实的信息 |

## 交给 Agent 使用

```text
使用 xhs-content-ops 分析“小红书 AI 教育”下 5 条高互动图文笔记。先做只读搜索和详情分析，用 Markdown 表格列证据，再给出 3 个差异化选题。不要发布、评论、点赞或收藏。
```

```text
先研究“企业 AI 培训”的热门笔记，再生成一条图文草稿。先填入发布页让我预览；只有我明确说“发布”后才能点击发布。
```

## 安全边界

- 搜索、详情和分析默认是只读动作；
- 发布、评论、回复、点赞和收藏都会改变外部状态，必须在执行前确认；
- 向用户报告当前处于研究、草稿、预览还是已执行阶段；
- 控制搜索、详情读取与互动频率，不做无人值守的高频运营；
- 不混用本项目之外的小红书工具，也不暴露登录态信息；
- 第三方内容与数据的使用应符合平台规则和适用法律。
